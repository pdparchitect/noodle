## [0.15.0] - 2026-11-26

### Added

- GitHub: two tools, each signing in with a code through a private GitHub App of its own that the organisation registers, with no client secret. **GitHub Detection**, formerly GitHub, keeps the audit log, people, teams and security alerts and its watch, and adds audit reads: the organisation's security settings and code security configurations, members and outside collaborators without two-factor authentication, other GitHub Apps installed, riskiest first, webhooks, each repository's secret scanning, push protection and default branch rules, deploy keys, fine-grained personal access tokens and requests, Actions settings and self-hosted runners, and SAML credential authorizations; its App holds only read permissions, closing the write access the old `security_events` scope carried. **GitHub Containment** removes members and outside collaborators, blocks users, demotes owners, takes people off teams, cancels invitations, revokes fine-grained tokens and SAML authorizations, deletes deploy keys, disables webhooks and Actions, cancels workflow runs, and reports leaked GitHub tokens to GitHub without signing in, never keeping the token. Each action waits for approval, and Pion records what undoing it takes first, such as a member's role or an outside collaborator's repositories, which its undo operations act from. Connect GitHub again with a GitHub App, as the new GitHub guide explains.
- Splunk, Elastic, Grafana Cloud, Self-Hosted Grafana, Sumo Logic, Tenable, Wiz, Proofpoint TAP, AbuseIPDB, Censys, CrowdSec CTI, GreyNoise, Have I Been Pwned, AlienVault OTX, Shodan, urlscan.io and VirusTotal have `check-access`: it tries the tool's key or token once for each part the tool reads and says on a line each whether it works, with the account, roles, plan and quota left where the service reports them, or exactly what to change. Most read the key's own account and spend no lookup; AbuseIPDB's and VirusTotal's spend one, as those services offer no other read. The Setup Guide has a chapter for each, and one, Threat intelligence lookups, for the nine lookup services: the access each asks for and why, the least to give it, plan limits and caveats.
- GitHub Copilot is a harness, off until turned on in **Settings › Harness**, with its usage reports to GitHub and its self-updates turned off.

### Changed

- Detection tools are held to reading wherever their access could change something. **AWS Detection** and **AWS Containment** each sign in as an IAM Identity Center user of their own, holding only that tool's permission set, as Identity Center gives a sign-in keys for every permission set its user holds; each `check-access` lists the roles its sign-in may take and warns, naming them, of any besides its own. **Grafana Cloud** and **Self-Hosted Grafana** refuse SQL holding, anywhere outside quoted text, a word that changes data or rights, such as a `WITH` that deletes or `SELECT … INTO`, or any comment; InfluxQL with `INTO`, `DROP` and the like; Flux calling `to()` or importing a package that could write or send; and queries over data sources of a kind Pion cannot check. Their Setup Steps ask for read-only database users behind each data source, the real guard. **Splunk** refuses `summaryindex`, `runshellscript`, DB Connect's `dbxquery`, `dbxoutput` and `dbxlookup`, `map`, `savedsearch`, `fit` and every macro, and its `check-access` warns of any capability that writes, such as `run_collect`, `run_custom_command` or an `edit_` one. **Duo Detection** no longer reads global settings, as Duo gives them only with the right to change them: untick **Grant settings** on its Admin API application. **Sumo Logic**'s role needs only **Create Access Keys**, never **Manage Access Keys**, which manages every user's keys, with its key scoped to **Run Log Search** and its search filter limiting the logs, and it refuses a query with the `save` operator, which writes a lookup table. **Google Cloud Detection** keeps the narrowest scopes Cloud Asset Inventory and Security Command Center offer, as neither accepts Google Cloud's read-only one, and its Setup Steps and `check-access` say plainly that only the account's viewer roles keep it to reading. The AWS, Google Cloud, Grafana, Splunk, Duo and Sumo Logic guides explain each.
- Agents' harnesses run with their usage and error reports to Anthropic, OpenAI, xAI and Meta turned off, using each one's own setting and the standard DO_NOT_TRACK.

### Fixed

- Signing in to MCP services that accept only apps they approved, such as Vercel, no longer fails with HTTP 400: Pion receives the sign-in on this Mac, on a random port it listens on only until the sign-in ends.

## [0.14.0] - 2026-11-25

### Added

- **Help › Setup Guide** and **Help › User Guide** open PDF guides published with each release, also linked from the download page: the Setup Guide for whoever prepares Pion's accounts and access, with a chapter for each service that needs the most setting up, and the User Guide for the people using Pion. Both grow as the documentation does.
- Hunt.io: two new tools, each with a key of its own. **Hunt.io Detection** looks attacker infrastructure up in Hunt.io: whether an IPv4 address hosts known malware or C2, is named in threat reports, is a TOR exit node or VPN and which threat actor it is linked to, then its network and the services Hunt.io saw on it; a domain's DNS, WHOIS and subdomains; a certificate by its SHA-256 fingerprint; the IOC Hunter reports that name an IP address, network or host, or the file hashes reported for an actor or malware family; a summary of an open directory AttackCapture indexed, never its files; and threat actors by name, alias or country. It only reads, never scans, submits or downloads anything, and says plainly when the organisation's monthly quota runs low or out; `check-access` shows the plan and the quota left. **Hunt.io** connects to Hunt.io's own MCP server with a dedicated MCP key, as its sign-in would need a client secret from Hunt.io. Hunt.io has no free plan, only paid plans from Researcher up and a 2-week trial. The new Hunt.io guide explains the access each tool asks for.

### Changed

- The welcome stamps PION on the screen letter by letter, in the blue lettering of Pion's artwork, each letter landing with a jolt, before the steps to get started appear.
- A new Pion starts with the Grid background moving behind its window; View › Background still turns it off. A background picked before is kept.

### Fixed

- A watched account with nothing new no longer reads all the way back to when watching started on every check, which in a large Google Cloud organisation cut the audit logs short and woke its agents again and again for nothing. Each check now reads back from the last one that found nothing new.

### Added

- Duo: two new tools on Duo's Admin API. **Duo Detection** reads one account: the authentication log by user, result, reason, factor, application and time, with where each attempt came from and the device that approved it; what administrators changed; the SMS and calls Duo sent; one user's status, phones, hardware tokens, security keys and bypass codes (counted, never shown); and, for an audit, users led by those in bypass status, unenrolled or locked out, administrators without a hardware token or security key, applications led by Admin API applications that can change Duo, phones led by jailbroken, unencrypted or unlocked ones, policies led by SMS or phone calls allowed, new users let in without a second factor and networks that skip Duo, bypass codes that never expire, and global settings; its alert watch wakes agents for fraud users report, attempts denied from anonymous networks or restricted locations, bypass codes made, users set to bypass, administrators and Admin API applications added, secret keys viewed, policy and settings changes, and Trust Monitor's events. **Duo Containment** disables or restores a user, takes them out of bypass status, deletes their bypass codes, removes a phone, hardware token or security key, and sends enrollment or Duo Mobile activation, each only once you approve it. Vercel's Enterprise Audit Log has no API, so Pion reads the Activity Log, and Vercel can't revoke another member's token through its API, so Containment removes the member instead. The new Vercel guide explains the access each tool asks for.
- Google Workspace Detection's `all-devices` lists every phone and tablet in the domain: who owns each, its model, OS and status, when it first and last synced, whether Google finds it compromised and its resource ID, approved ones first and longest unsynced first, with counts of those approved but not synced for months, blocked, pending and compromised, so an audit finds a phone sold or lost long ago but still approved. Agents can ask for one owner's, one status, or only those not synced for a number of days. It uses the read access to mobile devices the tool already has, so nothing changes in its setup.

It reads through the Cloud Identity API, which the setup now enables, with one new read-only scope, `cloud-identity.policies.readonly`, added under Data Access: sign Google Workspace Detection in again. `check-access` tries it.
- Okta Detection reads how the org is set up, for an audit. `sign-on-policies` lists the global session and authentication policies with every rule: whom it reaches by group, user and network zone, whether MFA or a phishing-resistant factor is required, and how long sessions and re-authentication last, led by gaps such as a password alone letting people in, sessions that never end or survive closing the browser, or rules that apply from any network. `mfa-policies` lists the authenticators and the enrollment policies, led by SMS, voice call or a security question allowed and policies that require nothing beyond a password and email. `password-policies` lists length, complexity, age, lockout and recovery, led by short or common passwords, no lockout and recovery or reset by SMS or a security question. The Read-Only Administrator already views them; the tool now asks for three more read-only scopes, `okta.policies.read`, `okta.authenticators.read` and `okta.networkZones.read`: grant them on the Okta app's Okta API Scopes tab and sign Okta Detection in again. `check-access` tries them.
- Microsoft Entra ID Detection reads how the tenant is set up, for an audit. `conditional-access` lists every Conditional Access policy with whom it includes and excludes, its apps, conditions and controls, led by whether MFA is required of all users and of each privileged role, whether legacy authentication is blocked, which policies only report, whom enforcing policies exclude, broad trusted locations and whether security defaults are on. `auth-methods-policy` lists which sign-in methods are on for whom, such as SMS, email codes and passkeys, with the registration campaign, how far the move from the legacy MFA settings has gone, and security defaults. Global Reader already reads them; the tool now asks for one more read-only permission, `Policy.Read.All`: add it to the app, grant admin consent and sign Microsoft Entra ID Detection in again. `check-access` tries them.
- Cloudflare Detection reads how zones are set up, for an audit. `zone-settings` reads, for one zone or every zone the token sees, the SSL/TLS mode, minimum TLS version, Always Use HTTPS, Automatic HTTPS Rewrites, HSTS, TLS 1.3, DNSSEC, Opportunistic Encryption, Security Level, Browser Integrity Check and the WAF managed rulesets deployed at the zone, led by weak settings: SSL/TLS Off or Flexible, a minimum TLS below 1.2, HTTPS not enforced, DNSSEC off or not yet in force, and paused zones. `dns-exposure` groups a zone's records that point outside it by the provider the target shows, such as Heroku, GitHub Pages, S3, Azure, Netlify, Vercel, Shopify or Zendesk, for you to confirm each is still in use, led by CNAMEs whose target doesn't resolve, marked possible takeover only at providers where such names have been claimed by others, CNAMEs to names in the zone no record answers and private addresses in public DNS; it looks the targets up at Cloudflare's own DNS-over-HTTPS resolver, which already holds the zone's records, without the token, at most 40 a run unless asked for up to 100, takes only NXDOMAIN or no address for not resolving, never visits a target, and never says a record can be taken over.
